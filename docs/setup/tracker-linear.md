# 3a. Tracker: Linear

- **Service identity**: a dedicated member of the workspace named after the product's service identity (the reference installation names it `spl-asdlc`), with an API key stored where the bridge runs. Every transition and comment the bridge writes is attributed to it, never to a person or to an LLM agent.
- **Statuses**: the team's workflow must contain a state named exactly as each canonical status (`docs/spec/03-vocabulary.md`), case included: "To Deploy", not "To deploy". The configuration maps no status. "To Deploy" and "Post Deploy" are usually created for this purpose; rename any state whose name differs. There is no "Todo": a ticket starts in Backlog, stays there once refined, and a person moves it to Ready when agents may take it; leave Linear's default "Todo" unused, or remove it.
- **Labels**: `Refined`, by which refinement marks a ticket refined while it stays in Backlog (an existing label of that name will do); `qa-finding`; the bridge creates `release/<product>-v<version>` labels as it goes, and the escalation label (`release.escalation_label`, default `blocked-by-human`) at the first escalation if the team lacks it. Optional: the no-deploy label (`tracker.no_deploy_label`, default `no-deploy`), which a person or refinement puts on a ticket with nothing to deploy, so that its merge moves it to Done; the bridge reads it and never creates it.
- **PR ↔ ticket link**: Linear's GitHub integration attaches a PR to an issue when the branch name or the PR body carries the issue id; the bridge reads attachments by PR URL. Turn **off** any Linear automation that moves issues on PR events: the bridge makes those moves, from the GitHub facts.
- **Team key**: `[tracker] team`, in `.spl-asdlc/config.toml` or its instance overlay.

**Verify**: `spl-asdlc doctor` reports `tracker: ok` with the identity's name, and `statuses: ok` when the team names every canonical status; otherwise it names each one the team lacks. `release.escalation_label` says whether the escalation label exists or will be created at the first escalation; `tracker.no_deploy_label` whether the no-deploy label exists, for information only.
