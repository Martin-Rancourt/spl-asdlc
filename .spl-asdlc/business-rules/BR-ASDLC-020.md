# BR-ASDLC-020 — A release angle's item follows the normal flow and is Done when its angle PR merges; the candidate's consolidation is the overall review, served only once every angle is merged.

Status: Enforced

## Rule

An angle PR carries the angle's report only, never a fix (BR-ASDLC-022): one that changes any other file is not merged, and is told so once per head, on the PR. An angle sub-item goes In Progress when its `qa/<candidate>/<angle>` PR to the release branch appears, In Review when that PR is ready (not draft) with its required checks green, back In Progress when a configured coordinator (`release.coordinators`) requests changes on it at its head, and Done when the bridge merges it, never To Deploy; only a PR that names its sub-item drives it (one that names none is told once per head, on the PR, which key to name), and a status and assignee already right are not written again. The coordinator reviews each angle PR as it comes, as its reviewer, served by assignment: the write that sets In Review assigns the item to `release.coordinator_assignee` (unset or unknown: the assignee is left as it is), the write that sends it back In Progress assigns it to the angle's configured `assignee` (none, or unknown: unassigned, taken by role), and Done leaves the assignee; its approval at the head lets the bridge merge it. The candidate's consolidation item is created with the round, blocked by every angle sub-item of that candidate through the tracker's `blocks` relation (written right after the items, repaired at later ticks, never written twice; a relation that cannot be read or written is reported and retried, and holds the brief, fail-closed: the brief, which starts the angles' work, is posted only at the tick that lays the last relation); it is the overall review (every merged report read together, each finding and whether it is blocking confirmed or rejected, nothing left between the angles, then the next candidate), and goes Done when a newer candidate is tagged or the release is published, the cycle's closure closing it otherwise (`docs/reference/05-release-cycle.md` §3–§5).

## Evidence

The owner's decision of 2026-10-09 on `.spl-asdlc/open-points.md` #15: blocking the release consolidation item by angle items that closed only at a merge which needed the coordinator, whom only that item served, would deadlock the cycle.
