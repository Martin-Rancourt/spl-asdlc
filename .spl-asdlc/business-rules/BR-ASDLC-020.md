# BR-ASDLC-020 — A release angle's item follows the normal flow and is To Deploy when the bridge merges its report, with no approval; the candidate's consolidation is the overall review, served only once every angle report is merged, and ends in the coordinator's committed verdict.

Status: Enforced

## Rule

An angle PR carries the angle's report only, never a fix (BR-ASDLC-022): one that changes any other file is not merged, and is told so once per head, on the PR. An angle sub-item is a ticket, its code the report (ASDLC-WMTX). It goes In Progress when its `qa/<candidate>/<angle>` PR to the release branch is opened, In Review when its agent moves it there once that PR is opened, so that it is not served again while the bridge checks the PR, or when that PR has its required checks green with no fault (a draft angle PR is out of the flow, as any draft: it drives nothing and is never merged), back In Progress when a configured coordinator (`release.coordinators`) requests changes on it at its head, or, its assignee kept, when a fault at its head is the angle's to mend (a required check red, its report missing or invalid, a change besides the report; pending checks are no fault), and To Deploy when the bridge merges it; only a PR that names its sub-item drives it (one that names none is told once per head, on the PR, which key to name), and a status and assignee already right are not written again. In Review is the bridge's own step, served to nobody: the item keeps its assignee; the write that sends it back In Progress assigns it to the angle's configured `assignee` (none, or unknown: unassigned, taken by role). The bridge merges an angle PR with no approval, once it names its sub-item, carries a valid report and nothing else, has its required checks green, is up to date with the release branch and no request for changes stands on it (a coordinator's at its head, a person's or an App's at any head: none is dismissed without an approval to supersede it). An angle item To Deploy goes Done when the release is published or a newer candidate is tagged.

The candidate's consolidation item is created with the round, assigned to `release.coordinator_assignee`, and served only once every angle report of the candidate is merged: on a tracker that keeps blocks freed at the blocker's merge (Livela's implementation blocks), it is created Ready and blocked by every angle sub-item of the candidate through such a block; otherwise it is created in Backlog and the bridge moves it to Ready once every offered angle's sub-item is To Deploy or later (and back to Backlog, from Ready only, should that stop holding). A release-kind block an older bridge laid from an angle is removed. A relation written right after the items is repaired at later ticks, never written twice; one that cannot be read or written is reported and retried, and holds the brief, fail-closed: the brief, which starts the angles' work, is posted only at the tick that lays the last relation. It is the overall review: every merged report read together, each finding judged once, what falls between the angles checked, ending in the coordinator's verdict committed from `qa/<candidate>/consolidation` (V7QD). It is a ticket, its code the verdict: its coordinator moves it In Review once the verdict PR is opened, and the bridge moves it back In Progress from In Review when what holds that PR is the coordinator's to mend (the PR names no item, carries another change or an invalid verdict, or a required check is red) or when no verdict PR is open (ASDLC-WMTX). It goes Done when the bridge merges that verdict, Canceled when a newer candidate is tagged while it is open (BR-ASDLC-038), Done when the release is published, the cycle's closure closing it otherwise (`docs/reference/05-release-cycle.md` §3–§5).

## Evidence

The owner's decision of 2026-10-09 on `.spl-asdlc/open-points.md` #15: blocking the release consolidation item by angle items that closed only at a merge which needed the coordinator, whom only that item served, would deadlock the cycle. The owner's decision of 2026-11-21, ASDLC-8SPA: the same deadlock came back through In Review, which a tracker that never serves its validation statuses never serves to the coordinator; two releases stalled with green, valid angle PRs no one approved. The angle's report now merges on the bridge's checks, and the coordinator judges in a committed verdict.
